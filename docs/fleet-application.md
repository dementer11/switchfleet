# SwitchFleet с исполнением через Ansible

Приложение предоставляет оператору единый интерфейс для импорта Excel, выбора
устройств, хранения учётных данных, просмотра плана и запуска заданий. Задания
исполняет Ansible Runner. Его action plugin открывает SSH-сессии через существующие
профили Netmiko и Paramiko. На коммутаторы не требуется устанавливать Python или
агенты.

## Запуск

Для Linux требуется Python 3.11 или новее с модулем `venv`:

```bash
bash scripts/install-fleet.sh
.venv/bin/switchfleet-ui
```

Интерфейс доступен по адресу `http://127.0.0.1:8787`. Данные по умолчанию
сохраняются в `~/.switchfleet`. Другой каталог можно задать параметром
`--data-dir /path/to/data` или переменной `SWITCHFLEET_DATA_DIR`.

Для Windows предназначена переносимая сборка: `Start-SwitchFleet.cmd` запускает
встроенную Linux-среду QEMU в фоне и открывает `http://127.0.0.1:18787`.
Компоненты Windows, WSL и Docker для неё не нужны. Приложение и Ansible уже
установлены в сборке. Сетевые подключения к выбранным коммутаторам выполняет
Linux-среда через сетевое подключение Windows. `Stop-SwitchFleet.cmd`
останавливает среду. Не запускайте несколько экземпляров с одним каталогом данных.

## Работа

1. Загрузите файл в разделе «Инвентарь». Поддерживаются XLSX, CSV и JSON.
   Для XLSX используются столбцы `Status`, `Device Label`, `Model`, `IP Address`,
   `Vendor`, `Device Category`, `Location`, `Contact`. Строка экспорта
   `Exported N records.` перед заголовками допускается. Исходные модели
   сохраняются наряду с нормализованными.
2. Создайте учётную запись в разделе «Учётные данные». Пароль SSH и дополнительный
   пароль enable шифруются локальным ключом. Для резервного копирования данных
   приложения нужно сохранять весь каталог данных вместе с `local.key`.
3. Выберите устройства флажками. Фильтры ограничивают отображение таблицы;
   счётчик выбранных устройств показывает фактическую область задания.
   Профиль, SSH-порт и отдельные учётные данные можно изменить у устройства.
4. Выберите операцию и создайте план. Планирование не открывает SSH-сессии.
   Неподдерживаемые устройства и операции перечисляются отдельно.
5. Просмотрите команды и запустите задание. Для операций записи требуется
   подтверждение плана. Перед записью исполнитель получает свежую конфигурацию;
   при ошибке или пустом ответе резервного копирования запись не начинается.
6. Результаты каждого устройства, ошибки и конфигурации доступны в «Заданиях»
   после завершения и повторного открытия приложения. Отмена останавливает
   дальнейшую обработку, но не отменяет уже отправленные устройству команды.

## Операции и профили

- `facts`: вывод версии оборудования и ОС.
- `backup`: получение текущей конфигурации.
- `commands`: явно заданные CLI-команды. Поскольку команды вводит оператор,
  они требуют подтверждения и предварительного резервного копирования.
- `configure`: полный построчный план CLI, включая вход и выход из режима
  настройки и команду сохранения, если она требуется.
- Создание VLAN, назначение access VLAN, описание и состояние порта, смена
  локального пароля: готовые шаблоны для поддерживаемых профилей.

Для Huawei VRP, HPE/3Com Comware, ProCurve, Cisco IOS и Dell используются
существующие шаблоны. Bulat, QTECH и Eltex допускают получение версии,
конфигурации и явно заданные команды; неподтверждённые стандартные шаблоны
изменений не подменяются командами другого производителя. Неизвестные и
web-only устройства требуют выбора подходящего профиля оператором.

Выбранный профиль означает способ построения и отправки команд. Наличие
профиля в программе не подтверждает совместимость каждой модели и прошивки.
Результат `commands_completed` означает, что команды завершились без
распознанных ошибок CLI. Он не является подтверждением конечного состояния
всех настроек. Автоматического отката в этом контуре нет.

Скачиваемые конфигурации и вывод команд скрывают распознанные секреты.
Такой файл подходит для анализа и сравнения; он не является полным образом
восстановления с исходными паролями и ключами.

## Хранение и границы доступа

Данные, задания и журнал сохраняются локально. Секреты не передаются в аргументах
командной строки Ansible или в inventory. Для каждого задания создаётся закрытый
временный каталог; после завершения он удаляется. Изменённый инвентарь или
профиль требует построения нового плана. Одновременные задания на один SSH
endpoint блокируются.

По умолчанию интерфейс предназначен для одного оператора на локальном компьютере.
Публичный сетевой доступ требует отдельной аутентификации и обратного прокси.
`--host 0.0.0.0` используется внутри переносимой среды, где наружу перенаправлен
только loopback-порт Windows. Загруженный реальный инвентарь и учётные данные
не включаются в исходники или переносимую сборку.

## Проверка

```bash
python -m pytest -q tests/fleet
```

`test_ansible_ssh_integration.py` запускает настоящий Ansible и локальный SSH
стенд на Paramiko. Он проверяет получение конфигурации, частичный сбой в группе
устройств и резервное копирование до записи. На Windows эти тесты явно
пропускаются: для них требуется Linux с Ansible. Они не используют пользовательский
инвентарь и не подключаются к его адресам.
